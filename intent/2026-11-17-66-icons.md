# Intent: Omarchroma Icons on NixOS

## Problem

#65 bumped Omarchroma to 4.1.0 but left out its Icons feature. Today
`pkgs/hyprchroma.nix:59` deletes upstream's `lib/hyprchroma-icons`, and
`pkgs/hyprchroma-icons-stub` takes its place: `status` and `revert` exit 0,
everything else prints "Icons is not available on NixOS (#66)". So the
panel's Icons page (key `6`), the bar's right-click "next folder colour" and
`hyprchroma icons …` do nothing on Nixarchy.

Upstream Icons (`lib/hyprchroma-icons`, 2,454 lines of Python, 4.1.0) does
this when switched on:

- every Omarchy theme points at one icon theme, `Omarchroma-Icons` in
  `~/.local/share/icons`, which inherits the Reversal or Yaru colour variant
  nearest the active theme's accent (`-dark` on a dark theme);
- folder icons are recoloured from the theme (sidebar highlight, accent,
  window border, or Yaru's own); Yaru's PNG folders are traced to SVG once;
- optional "covers": Reversal's rounded plate behind app icons the set lacks;
- GTK gets the icon theme through `gsettings`, KDE through a hidden
  `Omarchroma` theme falling back to Breeze, signalled over D-Bus.

What stops it running on NixOS:

1. **Hard-coded FHS paths.** Commands come only from root-owned
   `/usr/bin` and `/usr/share/omarchy/bin` (`trusted_path`, line 69); the
   shebang is `/usr/bin/python3 -I`; stock themes default to
   `/usr/share/omarchy/themes`; app icons are read from
   `/usr/share/pixmaps`.
2. **Dependencies.** Python Pillow (line 1255) and NumPy (line 2214, the
   Yaru tracer), plus `rsvg-convert`, `gtk-update-icon-cache`, `gsettings`
   and `gdbus` on that trusted path.
3. **Icon sets.** Upstream expects them from the AUR, and the panel offers
   to install Reversal when it is missing. nixpkgs has both:
   `reversal-icon-theme` (colour variants opt-in through `colorVariants`;
   no sage, which upstream covers itself) and `yaru-theme`. On NixOS they
   have to come from the configuration, and the helper finds them through
   `XDG_DATA_DIRS`.
4. **Theme directories.** It writes an `icons.theme` into
   `~/.config/omarchy/themes/<slug>/` for every theme, keeping a backup
   under its state dir, and treats a user theme directory holding only that
   file as its own. On Nixarchy the stock themes live in the store.

## Proposed outcome

On a Nixarchy host with Icons enabled in the configuration:

- the panel's Icons page works: switch Icons on and off, pick Reversal or
  Yaru, cycle folder colours, toggle covers;
- folders and the icon theme follow every theme change, in GTK and KDE
  apps, as on Arch;
- switching Icons off restores the icon theme Omarchy had set;
- with Icons not enabled, nothing changes from today: no icon packages, no
  writes, the stub's behaviour.

## Affected users and systems

- `pkgs/hyprchroma.nix` (stop deleting the helper; path and dependency
  wiring), `pkgs/hyprchroma-icons-stub` (kept for the off case or removed),
  `modules/nixos.nix` (an option, icon packages, session environment),
  `tests/`, docs and README.
- Nixarchy users who opt in. On the owner's fleet: p620 first; razer and
  p510 only if the owner enables it there.

## Constraints

- Opt-in, default off, so the closure of hosts that do not enable it does
  not grow (Pillow, NumPy, two icon sets with all Reversal variants are
  large).
- Keep upstream's safety properties: trusted command path (root-owned store
  paths instead of `/usr/bin`), Python isolation, the safe-io writes. Patch
  paths; do not weaken checks.
- No imperative package install: the panel's "install Reversal" offer must
  not try `pacman`/AUR on NixOS.
- Must pass upstream's own `tests/test-icons.sh` and
  `tests/test-icons-untrusted.sh`, adapted where they assume FHS paths.
- Must not touch the user's icon theme unless Icons is switched on, and
  `revert` must work after a rebuild that removes the option.

## Open questions

1. Option shape: one `icons.enable` that pulls in both sets, or a choice of
   which sets to install (Reversal with all colour variants is the biggest
   part)?
2. Should the configuration also set the starting state (Icons on, chosen
   set, folder mode), or only make the feature available and leave the
   panel in charge, as upstream does?
3. `/usr/share/pixmaps` for covers: read the system and per-user profile
   `share/pixmaps` instead, or leave covers to the icon sets only?
