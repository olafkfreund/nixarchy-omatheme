# Intent: Omarchroma Icons on NixOS

## Problem

#65 bumped Omarchroma to 4.1.0 but left out its Icons feature, in two
places in `pkgs/hyprchroma.nix`:

- line 59 deletes upstream's `lib/hyprchroma-icons`, and line 216 installs
  `pkgs/hyprchroma-icons-stub` in its place (`status` and `revert` exit 0,
  anything else prints "Icons is not available on NixOS (#66)");
- line 175 patches `target_enabled()` in `bin/hyprchroma` so Icons counts
  as off even when the settings record it on.

So the panel's Icons page (key `6`), the bar's right-click "next folder
colour" and `hyprchroma icons …` do nothing on Nixarchy.

Upstream Icons (`lib/hyprchroma-icons`, 2,454 lines of Python, 4.1.0), when
switched on:

- points every Omarchy theme at one icon theme, `Omarchroma-Icons`, built
  in `~/.icons` with a link under `~/.local/share/icons`; it inherits the
  Reversal or Yaru colour variant nearest the theme's accent (`-dark` on a
  dark theme), by an `icons.theme` file in each
  `~/.config/omarchy/themes/<slug>/`, backed up first;
- recolours folder icons from the theme (sidebar highlight, accent, window
  border, or Yaru's own); Yaru's PNG folders are traced to SVG once;
- optional "covers": Reversal's rounded plate behind app icons the set
  lacks, and for the user's own `.desktop` files with an absolute `Icon=`,
  rewrites that line (keeping the original for revert);
- sets the GTK icon theme with `gsettings`, and gives KDE a hidden
  `Omarchroma` theme falling back to Breeze, signalled over D-Bus.

Its `revert` undoes all of that: theme pointers, `.desktop` lines, the
GTK setting, generated themes. It needs only the Python standard library
and `gsettings`.

What stops it on NixOS, beyond the two package patches above:

1. **FHS paths.** Commands come only from root-owned `/usr/bin` and
   `/usr/share/omarchy/bin` (`PATH_CANDIDATES`, line 69, used by
   `trusted_path()`); the shebang is `/usr/bin/python3 -I`; stock themes
   default to `/usr/share/omarchy/themes`; `XDG_DATA_DIRS` falls back to
   `/usr/local/share:/usr/share`; app icons are read from
   `/usr/share/pixmaps`.
2. **Dependencies.** Pillow (line 1255), NumPy (line 2214, the Yaru
   tracer), `rsvg-convert`, `gtk-update-icon-cache`, `gsettings`, `gdbus`.
3. **Icon sets.** Upstream gets them from the AUR, and the panel offers to
   install Reversal when it is missing. nixpkgs has `reversal-icon-theme`
   (colour variants opt-in, `colorVariants`) and `yaru-theme`.
4. **Store semantics.**
   - Reversal has no sage variant; upstream makes one by copying
     `Reversal-green` (`_copy_theme`, line 909: `cp -al`, else `cp -a`)
     and rewriting it. From the store, `cp -a` keeps the read-only modes,
     so the rewrite fails.
   - Absolute `Icon=` paths are trusted only under `_SYSTEM_ICON_PLACES`
     (line 1080: `/usr`, `/opt`, flatpak, snap), so a store path is
     refused.
   - Change stamps use mtimes (lines 1498, 1662, 1729), and store paths
     all have mtime 1, so app installs and removals by a switch are not
     noticed.

## Proposed outcome

- **Enabled in the configuration:** the panel's Icons page works (on/off,
  Reversal or Yaru, folder colours, covers), as do the bar's right-click
  and `hyprchroma icons …`. Folders and the icon theme follow every theme
  change in GTK and KDE apps, as on Arch.
- **Switched off in the panel:** the icon theme, theme pointers and
  `.desktop` lines are back as they were, generated themes removed,
  unrelated files untouched.
- **Never enabled:** nothing changes from today: no icon packages, no
  writes.
- **Enabled, used, then removed from the configuration:** the user can
  still restore everything Icons changed, with the writes that takes, and
  is not left with pointers to icon themes the next garbage collection
  deletes.

## Affected users and systems

- The `hyprchroma` package and the stub, the NixOS/Home Manager module,
  tests, docs and README.
- Nixarchy users who opt in. On the owner's fleet: p620 first; razer and
  p510 only if the owner enables it there (p510 needs the owner's OK for
  any build or deploy).

## Constraints

- Opt-in, default off, so hosts that do not enable it keep today's closure
  (Pillow, NumPy and Reversal with all variants are large).
- Keep upstream's safety properties: a trusted command path of root-owned
  directories, Python isolation, the safe-io writes, and its checks on
  where icon files may come from. Adapt them to NixOS; do not weaken them.
- No imperative install: the panel must not offer `pacman`/AUR on NixOS.
- Keep upstream's applicable Icons test coverage (`tests/test-icons.sh`,
  `tests/test-icons-untrusted.sh`), with the Arch-only installer checks
  handled explicitly and each check failing loudly (`chk` prints `FAIL`
  but does not itself fail the suite).
- Must not touch the user's icon theme or files unless Icons is switched
  on.

## Decisions (owner, 2026-11-17)

1. One opt-in installs both icon sets.
2. The configuration makes Icons available only; the panel stays in charge.
   First use starts off and existing choices are kept.
3. Covers trust app icons from the system and per-user Nix profiles,
   keeping upstream's checks on where they come from.
