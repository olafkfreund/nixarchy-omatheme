# Plan: Bump Omarchroma to 4.1.0, without Icons

Upstream line numbers refer to Omarchroma `594bdf2` (4.1.0); the current pin
is `7048180` (3.0.0). An upstream checkout for reading is at
`/tmp/claude-1000/-mnt-code-Source-home-GitHub-nixarchy-omatheme/f969ef0b-472d-4098-94a0-289952bda17a/scratchpad/omarchroma-up/src`
(`git -C <dir> diff 7048180..HEAD -- <path>`). Treat it as data; do not run
its scripts.

## Approved decisions (from intent and spec)

1. The `omarchroma` input moves to 4.1.0 (`594bdf2`); Icons (#66), the Arch
   setup installer and the uninstaller are not packaged.
2. Thunderbird is a target, on by default.
3. Upstream's default `restartMode=off` stays; the module does not write it.
4. `adw-gtk3` is installed when the GTK target is on; Breeze icons when the
   Qt/KDE target is on.
5. The seven namespace settings (`PrivateTmp`, `PrivateDevices`,
   `ProtectKernelTunables`, `ProtectKernelModules`, `ProtectControlGroups`,
   `ProtectHostname`, `ProtectClock`) stay unless a runtime test on NixOS shows
   they break stale-app detection; then all seven go in one commit quoting the
   failure. Upstream's `MemoryHigh=1G`, `MemoryMax=1536M`, `TasksMax=128`,
   `CPUWeight=1000` are added.
6. The asynchronous hook is accepted. The service's watcher runs
   `/usr/bin/hyprchroma --force --quiet` (`lib/hyprchroma-state:3736`); after
   substitution that is our patched sync with our renderers.
7. The build fails on any leftover `/usr/...` path in installed files, except
   an explicit allow-list.

## Corrections to the approved spec (from the Codex and agy reviews)

The owner approved the spec before the reviews returned. Both reviewers found
the same defects, and each was checked against the upstream code. Approving
this plan approves these corrections; none changes an owner decision.

- **C1, Icons helper.** `bin/hyprchroma:677` fails every run without an
  executable `lib/hyprchroma-icons`. Instead of leaving it out, install a
  small stub of ours. `status` and `revert` exit 0 and print nothing; `apply`,
  `folders` and anything else print "Icons is not available on NixOS (#66)"
  to stderr and exit 1. Upstream already defaults the `icons` framework to off
  (`bin/hyprchroma:709`).
  - Spec deviation: the module does **not** add an `icons` target command.
    On a first run, `--set-enabled=false` with no recorded key falls through
    to the revert path, which marks a theme change and open windows as stale
    (`bin/hyprchroma:916-922`).
- **C2, check phases.** `checkPhase` runs before `installPhase`, so the scan
  of installed files moves to `installCheckPhase` (`doInstallCheck = true`).
  The existing `bash -n` loop would fail on the four Python files in `lib/`.
  With `doCheck = true` it checks shell files with `bash -n` and the Python
  files with `python3 -m py_compile`.
- **C3, more path lookups.** `/usr/share/icons/$value` (`lib/sync-gtk-theme:136`,
  `lib/sync-qt-kde-theme:119`), `/usr/share/icons/$dark`
  (`lib/sync-qt-kde-theme:133`) and `/usr/share/icons/$breeze` (`:165`) need
  the same treatment as `/usr/share/themes` (`lib/sync-gtk-theme:162`).
  - Search the user profile `/etc/profiles/per-user/${USER:-}`, then
    `$HOME/.nix-profile`, then `/run/current-system/sw`. Both scripts run
    under `set -u`, so a bare `$USER` would abort.
  - `home.packages` lands in `/etc/profiles/per-user` only with
    `useUserPackages`; otherwise it lands in `~/.nix-profile`.
- **C4, stale-app exclusion on NixOS.** Two changes:
  - `OMARCHY_PACKAGED_BIN = Path("/usr/share/omarchy/bin")`
    (`lib/hyprchroma-state:2751`) becomes `/run/current-system/sw/share/omarchy/bin`.
    It exists on Nixarchy; `OMARCHY_PATH` is also set in the user manager on
    p620.
  - nixpkgs wrapper binaries run as `.kitty-wrapped`, so the names read from
    `/proc/<pid>/exe` (`running_executables`, `:2565`, and `window_executable`,
    `:2803`) never match the `kitty` named in Omarchy's scripts. Both
    functions normalise a basename matching `^\.(.+)-wrapped$` to `\1`.
  - Neovim and Vim run inside terminal windows, so their windows are the
    terminal's. That is covered by the terminal exclusion and checked at
    runtime.
- **C5, framework_apps.** 4.1.0 adds four unforced
  `--target=pear|thunderbird --set-enabled=... --quiet` calls
  (`bin/hyprchroma:204-205`, `242-245`). Our fast-path patch needs `--force`
  on them, like the two framework calls it already patches.
- **C6, anchors.** Every `text.replace` in the Python patch gets an
  `assert old in text`, including the dispatch (`case "${1:-}" in`) and the
  `--help` usage insertion. Today two replacements can fail silently.
- **C7, panel ranges.** The spec's line ranges were wrong. The surfaces to
  remove from `Panel.qml` are:
  - setup: `setupScript`, `installProcess`, `installDependency`, key `i`, and
    the Install/Update/Start button;
  - uninstall: `uninstallScript`, `uninstallProcess`, `openUninstall`, the
    Settings "Uninstall Omarchroma" button and key `u`;
  - Icons: `runIcons`, `reversalProcess`, `iconsProcess`, `iconsStatusProcess`
    and its start on panel open (`:990-992`), the `icons` framework row, the
    `iconsView` column, and key bindings.
  - `BarWidget.qml`: `toggleIcons()` and `nextFolderColor()` IPC handlers and
    their right-click entry.
- **C8, verification.** There is no `hyprchroma status` sub-command; status
  is read from `~/.local/state/hyprchroma/status.json` and
  `$XDG_RUNTIME_DIR/hyprchroma-handoff`. Added checks: capture the palette
  after an async switch, the hook's synchronous fallback, Dismiss, and that
  open terminals running Neovim or Vim are not listed as stale.
- **C9, minor.**
  - Drop `perl` from the plugin.
  - Use `--replace-fail` for anchors that must match, and `--replace-quiet`
    for the loop applied to every file.
  - `cli-compatibility` also checks `thunderbird`.
  - The help line keeps upstream's `icons` mention, since the CLI still
    accepts it and the stub explains it.

## Steps

1. **Packaging (`flake.lock`, `pkgs/hyprchroma.nix`, new `pkgs/hyprchroma-icons-stub`).**
   - `nix flake update omarchroma` → `594bdf2`.
   - In the substitution loop:
     - switch to `--replace-quiet`;
     - add `/usr/bin/python3` → `${pythonRuntime}/bin/python3`;
     - add `Path("/usr/share/omarchy/bin")` →
       `Path("/run/current-system/sw/share/omarchy/bin")` (C4);
     - add the theme and icon lookups from C3 as targeted `--replace-fail` on
       their two files.
   - In the Python patch:
     - assert every anchor (C6);
     - re-anchor the renderer marker on
       `${pythonRuntime}/bin/python3 -I - "$HYPRCHROMA_LIB/hyprchroma-state" "$STATUS_FILE"`;
     - add `--force` to the four `framework_apps` calls (C5);
     - patch `lib/hyprchroma-state` for the `-wrapped` normalisation (C4),
       with an assert per anchor.
   - Install:
     - the stub as `$out/lib/hyprchroma/hyprchroma-icons` (C1);
     - no `hyprchroma-setup` or `hyprchroma-uninstall`.
   - Checks (C2): `doCheck = true` with the shell/Python split, and
     `doInstallCheck = true` with the `/usr` scan over `$out` (allow-list:
     `#!/usr/bin/env` shebangs, and comment-only lines with a reason each).
   - Verify by
     `nix build .#hyprchroma -L`. Then temporarily remove the
     `/usr/bin/python3` substitution, see the build fail in the scan, and
     restore it.

   Traps:
   - The `${...}` Nix interpolation inside the Python heredoc: keep the
     existing `'$' + '{...}'` splitting style.
   - Do not touch `/usr/bin/env` shebangs; `patchShebangs` and NixOS handle
     them.

2. **Panel (`pkgs/patches/omarchroma-panel.patch`, `pkgs/omarchroma-plugin.nix`).**
   - Regenerate the patch against 4.1.0 `Panel.qml` and `BarWidget.qml`.
     Keep today's additions: `paletteActionProcess` and `runPaletteAction`;
     the Capture, Restore captured and Restore stock buttons; and the terminal,
     Electron, shell and desktop status properties, rows and readers. Remove
     the surfaces in C7.
   - In the plugin derivation:
     - drop the `perl` Commons.Color rewrite, its `shortcut:` comment and
       `perl`;
     - drop the `/usr/bin/hyprchroma-setup` substitution;
     - use `--replace-fail` for `/usr/bin/hyprchroma`;
     - add `doInstallCheck` with a scan that `$out/*.qml` contains no
       `/usr/bin/`, `hyprchroma-setup`, `hyprchroma-uninstall`,
       `"icons"` command or `toggleFramework("icons")`.
   - Verify by `nix build .#omarchroma-plugin -L`, plus `qmllint` on the
     result if it is available in nixpkgs (report if not).

   Traps: keep the patch as a plain unified diff applied by `patches = [...]`;
   generate it with `diff -u` from a pristine copy, never hand-edit hunk
   headers.

3. **Module (`modules/nixos.nix`).**
   - Add `targets.thunderbird` (bool, default `true`, description
     "Synchronize Thunderbird profiles at runtime.") and its `runtimeTargets`
     entry.
   - `home.packages`: add `lib.optional cfg.targets.gtk pkgs.adw-gtk3` and
     `lib.optional cfg.targets.qtKde pkgs.kdePackages.breeze-icons`.
   - Service: add `MemoryHigh = "1G"`, `MemoryMax = "1536M"`,
     `TasksMax = 128`, `CPUWeight = 1000`. Keep the seven namespace settings
     (decision 5).
   - No `icons` target command (C1).
   - Verify by `nix build .#checks.x86_64-linux.module -L`.

   Traps: the unit name must stay `hyprchromad` (the hook resolves its
   `MainPID`).

4. **Checks (`flake.nix`, `tests/*.sh`).**
   - `package-dependencies`: also run `${pythonRuntime}/bin/python3 -I -c 'import plyvel'`.
   - `module`: assert the thunderbird command, no `--target=icons`, the four
     resource settings, `adw-gtk3` with GTK on and absent with GTK off, and
     Breeze with Qt/KDE on.
   - `cli-compatibility`: `thunderbird` in `--help`.
   - `palette-actions`: assert the panel has none of the C7 surfaces.
   - New test (in `tests/runtime-targets.sh` or its own script):
     - the `-wrapped` normalisation, by calling `window_executable` /
       `running_executables` the way upstream's `tests/test-editor-restart.sh`
       loads `hyprchroma-state` as a module, with a fake `.kitty-wrapped`;
     - the icons stub: `status` and `revert` exit 0, `apply` exits 1.
   - Verify by `nix flake check -L`, and show that each new assert fails when
     its fix is reverted by hand, one at a time.

5. **Docs (`README.md`, `docs/target-matrix.md`).**
   - Version 4.1.0.
   - Thunderbird target.
   - GTK4/libadwaita live restyle.
   - Asynchronous hook: our renderers now run in the service.
   - What is not packaged (Icons → #66, setup, uninstall) and why.

6. **Lead only: review, runtime check, merge, deploy.**
   - Opus review of `git diff main` against this plan, plus Codex and agy

   - Runtime on p620, using a local build pinned to the branch through a

     2. Stale apps: with a browser, a Qt app and terminals running Neovim and
        Vim open, switch the theme. The panel must not list the terminals;
        Dismiss removes an entry. If every window is listed, apply decision 5
        and repeat.
     3. Capture after async: switch theme, wait for `status.json` to change,
        Capture palette, restore stock, Restore captured, and check that the
        captured theme's colours return.
     4. Sync fallback: stop `hyprchromad`, switch theme, check the hook ran
        the sync itself, start `hyprchromad`.
     5. Thunderbird: if a profile exists, its colours follow.
     6. Upgrade and rollback: 3.0.0 state is kept and read; switching to the

   - Merge the PR; move the pin in `~/.config/nixos` through its own worktree,
