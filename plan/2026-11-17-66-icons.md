# Plan: Omarchroma Icons on NixOS

Worktree: `/mnt/data/vmtest/omatheme-66`, branch `feat/66-icons`.
`U` is upstream 4.1.0, `/nix/store/kg3km3n50rkf259ajrrsw4aahvdwlqgy-source`
(read only, do not run its scripts); `P` is `pkgs/`.

## Approved decisions (from intent and spec)

1. One option, `programs.nixarchyThemeEngine.icons.enable`, default
   false. On: the user's `home.packages` get
   `reversal-icon-theme.override { colorVariants = [ "all" ]; }` and
   `yaru-theme`, and the default `package` is built `withIcons = true`.
   Off: no icon packages, no Pillow or NumPy in the closure.
2. The configuration makes Icons available only; the panel turns it on.
   First use is off (upstream default), existing choices are kept.
3. Every build ships the real `lib/hyprchroma-icons`; the stub is
   deleted. Without `withIcons`, `status` and `revert` work and an apply
   fails with the helper's own message; the `target_enabled` icons patch
   stays only in that build.
4. NixOS paths: shebang, `PATH_CANDIDATES`, `/run/current-system/sw/share/omarchy`
   for stock themes, `dataDirs` for the `XDG_DATA_DIRS` fallback,
   `/run/current-system/sw/share/pixmaps`.
5. Store semantics: sage copied with `cp -rL --no-preserve=mode`, no
   hard-link attempt, marked `.omarchroma-generated` and removed by
   `revert`; `/nix/store` is a trusted icon place (owner decision A);
   change stamps include realpaths; `artwork_index` follows links;
   symlinked theme dirs and `icons.theme` files are skipped with a log
   line.
6. With the option off, `hyprchromad` runs
   `-<package>/bin/hyprchroma --target=icons --set-enabled=false --quiet --force`
   in `ExecStartPre`.
7. Panel: keep the Icons page and the bar's right-click; remove the
   install offer; tooltips name the option.
8. `gtk-update-icon-cache` is not added.
9. If the first apply on p620 comes close to upstream's 60 s
   `ICONS_SECONDS`, the cap is raised (spec, Risks).

## Deviations during implementation

- **D1 (step 5):** case 4 said a found artwork means "that app gets no
  cover". A cover is drawn *from* the app's artwork, so found artwork
  means the cover exists; without it there is nothing to draw. The test
  asserts the cover exists.
- **D2 (step 5):** the upstream-suite wrapper also seeds
  `~/.config/hyprchroma/palette.toml` from the seeded theme's
  `colors.toml` (the sandbox has no `omarchy` to resolve a palette) and
  copies the package's whole `lib/hyprchroma/` and `share/hyprchroma/`
  into `$REPO`. No upstream assertion beyond the setup block is dropped.
- **D3 (step 4, lead):** `installPending` and `installDependency` stay
  forbidden in the plugin's `installCheckPhase`, as before this change.
- **D4 (host check, owner decision 2026-11-17):** on p620 the option had no
  effect. nixarchy sets `programs.nixarchyThemeEngine.package` with
  `lib.mkDefault` (its `pkgs/theme-engine.nix`), which outranks an option
  default, so decision 1's "the default `package` is built `withIcons`" never
  applied and both the daemon and nixarchy's panel ran the build without
  Pillow. The option default is back to the plain package; with
  `icons.enable` the module sets `package` to the `withIcons` build at
  `lib.mkOverride 999`, one step above `mkDefault`. A user's own setting
  (priority 100) still wins. The `module` check covers both cases.
- **D5 (host check):** the first apply on p620 failed in the sage copy.
  nixpkgs' `reversal-icon-theme` ships links that point nowhere (300 errors
  for Reversal-green and -dark), and `cp -rL` exits 1 on them after copying
  everything else. `_copy_theme` now accepts a nonzero exit only when every
  stderr line is `cp: cannot stat ...: No such file or directory` (run
  with `LC_ALL=C`) and `index.theme` was copied; any other error raises. The
  `icons-nixos` sage fixture gains a link that points nowhere.
