# Plan: Omarchroma Icons on NixOS

Worktree: `/mnt/data/vmtest/omatheme-66`, branch `feat/66-icons`.
`U` is upstream 4.1.0, `/nix/store/kg3km3n50rkf259ajrrsw4aahvdwlqgy-source`
(read only, do not run its scripts); `P` is `pkgs/`.

## Approved decisions (from intent and spec)

1. One option, `programs.nixarchyThemeEngine.icons.enable`, default
   false. On: the user's `home.packages` get
   `reversal-icon-theme.override { colorVariants = [ "all" ]; }` and
   `yaru-theme`, and the default `package` is built `withIcons = true`.
   Off: no icon packages, no Pillow or NumPy in the closure.
2. The configuration makes Icons available only; the panel turns it on.
   First use is off (upstream default), existing choices are kept.
3. Every build ships the real `lib/hyprchroma-icons`; the stub is
   deleted. Without `withIcons`, `status` and `revert` work and an apply
   fails with the helper's own message; the `target_enabled` icons patch
   stays only in that build.
4. NixOS paths: shebang, `PATH_CANDIDATES`, `/run/current-system/sw/share/omarchy`
   for stock themes, `dataDirs` for the `XDG_DATA_DIRS` fallback,
   `/run/current-system/sw/share/pixmaps`.
5. Store semantics: sage copied with `cp -rL --no-preserve=mode`, no
   hard-link attempt, marked `.omarchroma-generated` and removed by
   `revert`; `/nix/store` is a trusted icon place (owner decision A);
   change stamps include realpaths; `artwork_index` follows links;
   symlinked theme dirs and `icons.theme` files are skipped with a log
   line.
6. With the option off, `hyprchromad` runs
   `-<package>/bin/hyprchroma --target=icons --set-enabled=false --quiet --force`
   in `ExecStartPre`.
7. Panel: keep the Icons page and the bar's right-click; remove the
   install offer; tooltips name the option.
8. `gtk-update-icon-cache` is not added.

## Rollback

Switch Icons off in the panel on every host that used it, then revert the
merge. The order matters: the revert brings the stub back, whose `revert`
does nothing, and removes decision 6's `ExecStartPre`.
