# Spec: Replace the inline plugin QML rewrite

## Design

Add a checked-in patch under `pkgs/patches/` that changes the upstream
Omarchroma `Panel.qml` in one reviewable diff. The patch will add the current
runtime status properties, file watchers, status labels, palette action
process, and palette action controls currently generated by the embedded
Python rewrite.

Keep `pkgs/omarchroma-plugin.nix` responsible only for Nix-specific path
substitution and package installation. Apply the patch through the derivation's
normal patch phase, before substitutions replace the engine paths.

The patch must target the pinned Omarchroma source revision. A marker mismatch
will fail the build instead of producing a partially modified plugin.

## Alternatives rejected

- Keep the embedded Python rewrite: it hides a large QML change inside a Nix
  string and is harder to review or update.
- Maintain a complete fork of `Panel.qml`: it duplicates upstream UI code and
  increases merge burden.
- Generate a second plugin at runtime: it moves a build-time source problem
  into a less deterministic runtime path.

## Risks

- An Omarchroma update may require updating the patch context.
- A patch transcription error could remove a status display or palette action;
  existing package and runtime tests must catch this.
- The generated plugin must continue to use Nix store paths for the engine.

## Verification

- Build `.#omarchroma-plugin` and the default package.
- Run `.#checks.x86_64-linux.palette-actions`.
- Run the desktop, electron, runtime-target, and plugin-enable checks.
- Inspect the final `Panel.qml` for all status watchers and palette actions.
