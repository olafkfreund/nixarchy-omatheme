# Spec: Omarchroma Icons on NixOS

Paths: `U` is upstream 4.1.0 (`omarchroma` input,
`/nix/store/kg3km3n50rkf259ajrrsw4aahvdwlqgy-source`); `P` is `pkgs/`.

## Design

### 1. One option

`programs.nixarchyThemeEngine.icons.enable`, default `false`, in
`modules/nixos.nix`. When true:

- the user's `home.packages` get `reversal-icon-theme.override
  { colorVariants = [ "all" ]; }` and `yaru-theme` (owner decision 1), so
  they appear under `/etc/profiles/per-user/<user>/share/icons`, which is
  already on the helper's `XDG_DATA_DIRS`;
- the default `package` is built with `withIcons = true` (section 2).

Nothing else: the panel stays in charge, and Icons starts off, because
upstream's `target_enabled` already defaults it off (`U/bin/hyprchroma:707-709`)
and the module's `runtimeTargets` leave it out (`modules/nixos.nix:57-60`).
Owner decision 2.

### 2. The package always ships the real helper (`P/hyprchroma.nix`)

- Stop deleting `lib/hyprchroma-icons` (line 59) and stop installing
  `P/hyprchroma-icons-stub` (line 216); delete the stub. The helper's
  `revert` needs only the standard library and `gsettings`
  (`U/lib/hyprchroma-icons:2121-2160`), so every build can undo Icons.
- New argument `withIcons ? false`. With it, the Python env adds `pillow`
  and `numpy`, and `trustedBins`/`trustedPath` (lines 24-25) add
  `${librsvg}/bin` for `rsvg-convert`. Without it, the helper's lazy
  imports (`_pil()`, `_numpy()`) fail with its own message on apply, and
  `status`/`revert` work.
- `target_enabled`'s icons patch (line 175) stays, but only when
  `withIcons` is false: a host without the option never runs the Icons
  sync lane, so a recorded `true` from earlier does not report `missing`
  or `failed` on every theme change.
- `gtk-update-icon-cache` is left out: it is optional (`shutil.which`,
  line 926) and only speeds lookups; `gtk3` would add about 295 MiB.
- Checks: `bash -n` on the helper (line 235) becomes `py_compile`; the
  `/usr/` grep in `installCheckPhase` (line 238) now covers the helper.

### 4. Store semantics (patches to the helper, applied with `assert old in text` like the existing ones)

- **Sage copy** (`_copy_theme`, line 909, called from
  `ensure_reversal_sage`, line 936). On NixOS the source is a read-only
  store tree on another filesystem: `cp -al` fails with EXDEV and leaves a
  partial tree of 0555 directories that `remove_tree` then cannot delete,
  and `cp -a` keeps the read-only modes so the rewrite fails. On NixOS
  Reversal always comes from a profile, so the hard-link attempt is
  dropped and the copy is always `cp -rL --no-preserve=mode`. `-L` also
  resolves the `jdupes --link-soft` relative links into sibling themes
  that would otherwise dangle in `~/.local/share/icons/Reversal-sage`.
- **Sage on revert.** Upstream's `revert` keeps the sage variant on
  purpose (line 2126); the intent's "generated themes removed" does not.
  `ensure_reversal_sage` writes a marker `.omarchroma-generated` into the
  sage directories it creates, and `revert` removes the sage directories
  that carry it. A `Reversal-sage` the user made is left alone.
- **Trusted icon places** (line 1080, used by `icon_source`, line 1115).
  **Owner decision 2026-11-17: A, trust `/nix/store`.** The helper compares realpaths, and
  a profile's icon resolves to `/nix/store/<package>/...`; Nix-built
  `.desktop` files also often name `/nix/store/...` directly. Two ways:
  - **A, trust `/nix/store`** (recommended): add it to
    `_SYSTEM_ICON_PLACES`. Store objects are root-owned and immutable,
    so the checks upstream guards against (files another user can
    change, swaps between check and read) cannot happen there; upstream
    already accepts icons under the user's own home. Any store object
    qualifies, not only installed ones.
  - **B, profiles only:** accept an absolute `Icon=` only when the path
    as written starts with `/run/current-system/sw`,
    `/etc/profiles/per-user/<user>` or `~/.nix-profile` and resolves
    into `/nix/store`. Apps whose `.desktop` names `/nix/store/...`
    directly get no cover.
  The home-folder checks are unchanged either way.
- **Change stamps.** `_mtime` (line 1496, used at 1504-1542) returns the
  realpath with the mtime, and `icon_apps_signature`
  (`U/bin/hyprchroma:579-588`) stats `-L` and prints `readlink -f` too. A
  switch gives every merged profile directory a new store path, so app
  installs and removals now change the stamp; store mtimes are all 1.
- **Walking symlinked dirs.** `_walk_icons` (line 853, `follow=False` by
  default) as called from `artwork_index` (line 995) does not follow
  links, so
  profile entries that are store symlinks (`hicolor/128x128@2`,
  `Adwaita`) are skipped and those apps look iconless. They walk with
  `followlinks=True` under `XDG_DATA_DIRS` roots; store trees have no
  cycles.
- **Symlinked theme files.** `write_theme_pointers` (line 1929) skips,
  with a log line, a `~/.config/omarchy/themes/<slug>` directory or
  `icons.theme` that is a symlink (Home Manager), instead of writing into
  the store or replacing the link and deleting it on revert.

### 5. Removing the option reverts (`modules/nixos.nix`, the `hyprchromad` unit)

With `icons.enable` false, the unit's `ExecStartPre` gains
`-${cfg.package}/bin/hyprchroma --target=icons --set-enabled=false --quiet --force`
(`-`: a failure does not stop the daemon). `--force` is needed: our package
patch exits early when the recorded setting already equals the requested
one (`P/hyprchroma.nix:145-160`), which would skip cleanup left after a
panel-off that did not finish; framework removal uses `--force` for the
same reason (line 164). Upstream runs the revert only when
`$STATE_DIR/icons` exists (`U/bin/hyprchroma:879-886`), so on a host that
never used Icons it is a no-op. Turning the option off changes the
unit, so the switch restarts it and the revert runs then, inside the
session, where `gsettings` works. That meets the intent's
"enabled, used, then removed" outcome; the generated theme names its base
by name, so nothing pins or points into a store path GC can delete.

### 6. Panel (`P/patches/omarchroma-panel.patch`, `P/omarchroma-plugin.nix`)

The patch removes the whole Icons UI today (about 600 lines). It becomes:
keep the Icons page and the bar's right-click; remove only the install
offer. The `Install Reversal... (r)` button (`U/Panel.qml:2069-2078`) is
not shown, `setIconSet`'s install branch (656-663) and the `r` key (893)
do nothing when Reversal is not installed, `reversalProcess` and
`installReversal` (666-676) and `setupScript` (249) are removed, and the
tooltips at 1947 and 1949 say "not installed: set
programs.nixarchyThemeEngine.icons.enable". With the option off, the sets
are missing and the page says so. `installCheckPhase`
(`P/omarchroma-plugin.nix:50`) no longer forbids the Icons strings and
forbids `installReversal`, `reversalProcess`, `pacman` and `setupScript`.

### 7. Tests (flake checks)

- **Upstream suites** run against the `withIcons` build in the sandbox:
  `tests/test-icons.sh` and `tests/test-icons-untrusted.sh` with their own
  throwaway `HOME`, `XDG_DATA_DIRS`, `OMARCHY_PATH` and
  `HYPRCHROMA_ICONS_ISOLATED=1`. Dropped, each with a comment: the
  `hyprchroma-setup` section (lines 159-202, not shipped) and the two
  `Panel.qml` greps (they read upstream's file). The `/usr/bin/python3`
  of the untrusted suite (line 12) is substituted. `chk` only prints
  `FAIL`, so the check fails on any `FAIL` line in the output.
- **New cases** (`tests/icons-nixos.sh`, against fixtures):
  1. sage from a read-only (0555/0444) `Reversal-green` fixture whose
     files are relative links into a sibling theme → created, writable,
     recoloured, no dangling links, marker present;
  2. cover sources (per decision 3): an `Icon=` resolving under the
     store-place constant (pointed at a fixture root for the test) →
     accepted; one under `$HOME/../elsewhere` → refused;
  3. a profile directory re-pointed to another tree with the same mtime
     → the apps stamp (Python and shell) changes;
  4. artwork reached only through a symlinked directory in a fixture
     profile → found, so that app gets no cover;
  5. a symlinked theme directory, and a symlinked `icons.theme` in a real
     directory → both skipped with a log line, links intact, and revert
     leaves them intact;
  6. removal through the real command, `hyprchroma --target=icons
     --set-enabled=false --quiet --force`, on the build without
     `withIcons`, after an apply by the `withIcons` build, with the
     settings already recording `false` → theme files, `.desktop` lines
     and generated themes (sage included) restored or removed; without
     `--force` the same setup leaves them (proves the flag matters);
  7. a user-made `Reversal-sage` without the marker survives revert.
- **Module eval:** option off → no `pillow` in the package closure, no
  icon sets in `home.packages`, revert in `ExecStartPre`; option on → the
  sets in `home.packages`, no revert line.
- **Plugin:** the existing installCheck greps (section 6).

## Alternatives rejected

- **Keep the stub when the option is off.** Breaks revert after removal
  (the stub's `revert` is a no-op).
- **Always ship Pillow and NumPy.** About 700 MiB more closure for every
  host, against the intent's opt-in constraint.
- **Choice of icon sets.** Owner decision 1.
- **Profile-only cover sources.** Not checkable with realpaths (section 4).
- **Revert from Home Manager activation.** The activation runs outside the
  session, where `gsettings` may not reach dconf; the unit runs inside.
- **Two panel variants** (Icons hidden when off). Twice the patch to keep
  in step with upstream; the page already explains a missing set.

## Risks

- **First apply time:** two theme copies (now dereferenced, so larger),
  the Yaru trace and Pillow over about 400 desktop entries, inside
  upstream's 60 s `ICONS_SECONDS`. Measured on p620; if it is close, the
  plan raises the cap.
- **Disk:** a dereferenced sage copy in `~/.local/share/icons`; Reversal
  with all colour variants is not in the binary cache, so its size is
  measured in the plan.
- **Omarchy's own `omarchy-theme-set-icons`** links drawn icons into
  `~/.local/share/icons/hicolor/scalable/apps`, which `artwork_index`
  also scans. The interaction is untested; checked on p620.
- **Upstream drift:** every helper patch asserts its old text, so an
  Omarchroma bump that moves the code fails the build.
- **Panel patch size:** narrower than today's, but still the largest
  patch in the repo.
