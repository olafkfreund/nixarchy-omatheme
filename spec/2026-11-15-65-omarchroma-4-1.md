# Spec: Bump Omarchroma to 4.1.0, without Icons

Upstream line numbers refer to Omarchroma `594bdf2` (4.1.0); the current pin
is `7048180` (3.0.0).

## Design

### 1. Input

Update the `omarchroma` input in `flake.lock` to `594bdf2`
(`nix flake update omarchroma`). `flake.nix` keeps its unpinned
`github:NobleDoodle/omarchroma` URL, as today.

### 2. `pkgs/hyprchroma.nix`

**Python path.** Upstream now calls `/usr/bin/python3 -I` in 17 places,
including `#!/usr/bin/python3 -I` shebangs (for example `lib/hyprchroma-state`
and the status update at `bin/hyprchroma:1555`). Add one substitution
`/usr/bin/python3` → `${pythonRuntime}/bin/python3` to the existing loop, so
every call gets the interpreter that has `plyvel`. `-I` ignores `PYTHON*`
variables and the user site, so a check runs
`${pythonRuntime}/bin/python3 -I -c 'import plyvel'` (see Risks).

**Renderer hook marker.** Our Python patch inserts the terminal, shell and
editor renderers before the status update. Match it on the part that did not
change, after the interpreter:
`-I - "$HYPRCHROMA_LIB/hyprchroma-state" "$STATUS_FILE"` preceded by the
substituted interpreter path, and keep the `SystemExit` when it is missing.
The other three anchors (`case "${1:-}" in`, the `settings_key=` line and the
two framework `--set-enabled` calls) are checked against 4.1.0 while
implementing; any that moved is re-anchored the same way, never dropped.

**Fail loudly.** Today a pattern that stops matching only prints a warning,
which is how this bump nearly broke silently. Add to `checkPhase` a scan of
the installed files (`$out/bin`, `$out/lib/hyprchroma`, `$out/share/hyprchroma`,
the unit file) that fails on any remaining `/usr/bin/`, `/usr/lib/` or
`/usr/share/` path, except an explicit allow-list:

- `/usr/bin/env` in shebangs, which NixOS provides;
- `/usr/local/...` and `/usr/share/...` entries that are only one of several
  search locations next to `XDG_DATA_DIRS` (listed in the check with a reason
  each).

`checkPhase` only runs with `doCheck = true`; set it, so the scan runs in
every build.

**GTK and Qt theme lookups.** Two runtime lookups search only `/usr/share`:

- `lib/sync-gtk-theme:162` (`gtk_theme_installed`) checks `/usr/share/themes`
  and then `XDG_DATA_DIRS`;
- `lib/sync-qt-kde-theme` checks `/usr/share/icons/$breeze` for the new Breeze
  fallback in the hybrid `Omarchroma` Qt icon theme.

The systemd user service is not guaranteed to inherit the session's
`XDG_DATA_DIRS`. Substitute both with the NixOS profile directories,
`/etc/profiles/per-user/$USER/share/...` and `/run/current-system/sw/share/...`.

**Installed files.** Stop installing `bin/hyprchroma-setup` (Arch installer:
sudo, AUR, `pacman`). Do not install `bin/hyprchroma-uninstall` or
`lib/hyprchroma-icons`. The other `lib/` files stay as today.

**Unit file.** We keep shipping upstream's unit in `$out/lib/systemd/user`
for reference only; the module defines its own service (section 4).

### 3. `pkgs/omarchroma-plugin.nix` and the panel patch

- Remove the Qt 6.12 `perl` rewrite and its `shortcut:` comment: 4.1.0
  already reads `Commons.Color`.
- Regenerate `pkgs/patches/omarchroma-panel.patch` against 4.1.0's
  `Panel.qml`. It keeps what it adds today: palette capture and restore
  actions, and the terminal, Electron, shell and desktop status rows. It also
  removes the controls that do nothing on NixOS: Icons
  (`Panel.qml:260-278`, `500-505`), setup and uninstall (`648-700`).
- Drop the `/usr/bin/hyprchroma-setup` substitution. Add the
  `/usr/bin/python3` one if the panel calls it.

### 4. `modules/nixos.nix`

**Thunderbird target.** Add `targets.thunderbird` (bool, default `true`,
owner decision 1) to the options and to `runtimeTargets`, so the service runs
`hyprchroma --target=thunderbird --set-enabled=true --quiet` before start,
like the other targets. Upstream's own default is `false`; ours wins because
the module sets it.

**Icons off.** Add `{ name = "icons"; enabled = false; }` to `runtimeTargets`
with no option, so a settings file from an Arch install or the panel cannot
leave the Icons framework on. `hyprchroma-icons` is not installed, so it must
not be attempted.

**Restart mode.** Leave upstream's default `restartMode=off` (owner decision
2). The module does not write it.

**Packages.** When `targets.gtk` is on, add `pkgs.adw-gtk3` to the user's
packages (owner decision 3). When `targets.qtKde` is on, add
`pkgs.kdePackages.breeze-icons`, so the new Qt icon fallback has Breeze to
inherit from; without it the fallback is skipped, which is today's behaviour.

**Service.** Keep the unit name `hyprchromad`: the hook asks
`systemctl --user show -p MainPID hyprchromad.service`.

- Add upstream's resource settings (`MemoryHigh=1G`, `MemoryMax=1536M`,
  `TasksMax=128`, `CPUWeight=1000`, from `packaging/systemd/hyprchromad.service:51-59`).
- Keep the seven namespace settings (`PrivateTmp`, `PrivateDevices`,
  `ProtectKernelTunables`, `ProtectKernelModules`, `ProtectControlGroups`,
  `ProtectHostname`, `ProtectClock`) unless the runtime check in Verification
  shows they break stale-app detection (owner decision 5). If it does, remove
  all seven in one commit that quotes the observed failure. Upstream says each
  needs a private mount namespace, which in a user manager means a user
  namespace from which other processes cannot be read.

### 5. Asynchronous hook

4.1.0's hook signals the service (SIGUSR1) and returns (owner decision 6). The
service's watcher then runs `/usr/bin/hyprchroma --force --quiet`
(`lib/hyprchroma-state:3736`), which our substitution points at our package.
That is the same patched sync path, so our renderers still run, now in the
service. When the service is not listening, the hook falls back to running
the same command itself. Palette capture is a manual panel action, not part
of the hook, so it is not affected.

### 6. Documentation

Update `README.md` (version, Thunderbird, what is left out and why, with a
link to #66 for Icons) and `docs/target-matrix.md` (Thunderbird row; GTK4
live restyle).

## Alternatives rejected

- **Bump the lock only and fix warnings later.** The build fails outright,
  and the missing substitutions would leave `/usr/bin/python3` calls that do
  not exist on NixOS.
- **Fork Omarchroma with Nix patches applied.** It doubles maintenance.
  `substituteInPlace` plus a scan that fails the build stays reviewable here.
- **Package the Icons feature now.** It needs Nix packages for the Reversal
  and Pillow icon sets and NumPy/Pillow for the helper. Owner decision 4
  moves it to #66.
- **Use upstream's unit file directly.** Our unit adds `ExecStartPre` target
  commands and the Stylix mode environment. Copying upstream's limits into
  ours is smaller.
- **Drop the seven namespace settings up front.** The owner chose to remove
  them only on evidence.

## Risks

- **`python3 -I` and plyvel.** `-I` implies `-E` and `-s`. The
  `python3.withPackages` environment finds its packages through its own
  prefix, not through `PYTHONPATH`, so plyvel should still import. The
  `package-dependencies` check will run it with `-I` to prove it. If that
  fails, the Dark Reader target breaks on every host.
- **Stale-app detection under our sandbox.** If the seven settings hide other
  processes, the daemon may list every window as stale and write under
  running browsers (upstream's report). The runtime check covers this before
  merge, on p620 first.
- **State files.** 4.1.0 adds settings keys (`appsSaved`, `restartMode`,
  `staleDismissed`) and status fields. A rollback to the 3.0.0 generation
  reads files with unknown keys. Upstream's readers use `.get` with defaults,
  so this should be harmless, but the Verification checks it.
- **The panel patch is the largest edit.** A wrong hunk only breaks the panel,
  not the sync. The `palette-actions` check covers its own buttons, and the
  plugin is reviewed on p620.
- **Async ordering.** Other theme-set hooks may now run before our renderers
  finish. No hook in this repo depends on that order. A user's own hook could
  see the old terminal files for up to one sync.
- **Hosts.** Everything runs on p620 first, then Razer. p510 is not touched
  without the owner's OK.

## Verification

1. `nix build .#hyprchroma .#omarchroma-plugin` succeeds, and the new
   `checkPhase` scan finds no unlisted `/usr` path. Proof that the scan bites:
   temporarily remove the `/usr/bin/python3` substitution, and the build
   fails.
2. `nix flake check` passes. The existing checks are `package`,
   `palette-actions`, `package-dependencies`, `desktop`, `electron`,
   `runtime`, `editors`, `cli-compatibility`, `plugin-enable` and `module`.
   Additions:
   - `package-dependencies` also runs `python3 -I -c 'import plyvel'`;
   - `module` asserts the `thunderbird` and `icons` target commands, the
     resource limits, `adw-gtk3` with GTK on and Breeze with Qt/KDE on;
   - `palette-actions` (or a new grep in it) asserts the panel no longer calls
     `hyprchroma-setup`, `hyprchroma-uninstall` or `--target=icons`.
3. Runtime on p620, after a switch:
   - Theme switch: terminals, shell, Neovim/Vim, GTK3 and Qt follow the new
     theme. An open Nautilus restyles without a restart. The hook returns
     before the sync finishes, and `hyprchroma status` reports success
     afterwards.
   - Stale-app detection: with a browser and a Qt app open, after a switch
     the panel lists only the apps that truly keep the old theme, not every
     window. If it lists every window, apply decision 5 and repeat.
   - Thunderbird: with a profile present, its colours follow a switch.
   - Upgrade: existing `~/.local/state/hyprchroma` and settings files from
     3.0.0 are kept and read; a captured palette restores correctly.
   - Rollback: switching back to the previous generation starts the 3.0.0
     service without errors against the 4.1.0 state files.
4. Razer: deploy from `main` after merge; check that the service is active,
   no units failed, and one theme switch is followed.
